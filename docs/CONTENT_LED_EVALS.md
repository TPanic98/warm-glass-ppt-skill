# 内容驱动的陌生材料验收

本文件是待执行的 agent 行为测试，不是通过记录。自动生成器测试不能替代它。采用全新会话，只给技能、下面的一项真实式任务和必要原始材料；不额外提示需要选哪个组件或模仿哪页样例。产物留在临时目录，不发布到远程账户。

`1.3.0-alpha.2` 增加了四类不同虚构材料的编排与生成回归用例，位于 `examples/compose/`，另有文件状态与审阅协议测试。这些由技能维护者编写的用例不是此处所述的独立 agent 盲测，也不证明 WorkBuddy 已完成新版本复测。

## 任务

| 用途 | 给执行者的任务 | 验收关注点 |
| --- | --- | --- |
| 汇报 | 某项目有两条并行工作线，各有不同里程碑，同时存在一项待领导决定的资源取舍。根据提供的计划与进展整理汇报，保留双方日期与责任。 | 计划、实际与待决策事项分清；并行关系与粒度保留，不因为卡片数量而改事实。 |
| 演讲 | 给非技术听众解释“交付结果为什么还需要检查”，提供一段经历和一项有出处的观察，演讲时长约 8 分钟。 | 叙事围绕一个可理解的主张，案例讲清机制；页面密度随解释需要变化，未把汇报目录机械搬入。 |
| 培训 | 为新员工准备一节处理含糊需求的短课，材料包含原始请求、澄清过程、修改前后任务说明和练习要求。 | 概念、示例、练习与评价依据可对应；前后对照真实可读，练习不是一句泛泛口号。 |
| 产品介绍 | 介绍一个面向现场巡检的虚构协作产品，材料含用户困扰、一次巡检的使用流程、现有能力、限制和试用条件。 | 产品围绕用户任务讲清流程；已具备与计划能力分开，架构仅在帮助判断时出现，不用技术堆栈替代价值。 |

## 记录

记录执行宿主、模型与版本、技能版本、原始请求、页计划、输入／素材／最终 PPTX 哈希，以及实际页面截图。检查：

- 是否遵守用户页数、事实、品牌和可编辑要求。
- 页面关系是否由材料决定，而非只替换示例文案。
- 需要方向、包含、对照或并行的关系是否在画面中成立。
- 标题层级、品牌及 slogan 是否来自用户，而非残留示例。
- 全稿节奏与逐页可读性是否通过实际 PPTX 渲染检查。

字体、转换和目标应用交互分别记录。缺少目标应用时写明未测。保留合理的重复表格或平行对照；不以“每页必须长得不一样”替代内容判断。未经新的真实产物验证，不把某次观察提升为全局硬规则。
