# Page selection and capacity

| Layout | Relationship | Data and practical capacity |
|---|---|---|
| `cover` | Opening subject and promise | Title, subtitle, optional illustration and up to 3 short lines |
| `section` | Chapter transition | Module label, title, one paragraph, optional illustration |
| `columns` | Parallel pillars or categories | 2–4 items, each with heading and 1–4 short details |
| `comparison` | Before/after or alternatives | Exactly 2 items, each with heading and up to 4 details |
| `process` | Ordered steps | 3–6 items; step label and short description |
| `roadmap` | Dated milestones | 3–5 items; date, heading and up to 3 short details |
| `layers` | Containment or conceptual depth | 2–4 items; label and one description |
| `architecture` | Stacked capability or system domains | 3–5 rows; heading and 2–4 components per row |
| `metrics` | Measured results | 2–4 values with label, definition and source; mark demonstration data |
| `quote` | A decisive statement or closing thought | Title and message; optional illustration |
| `image` | One supplied or generated visual | Image, editable title/caption; notes carry source and limitations |

Cover, section and image layouts can carry rich 3D art. Flow and architecture relationships use native shapes. Do not force a map into a slide that expresses no geographic or journey relationship.

The reusable generator is deliberately bounded. If a source table, data chart or specialized diagram is required, use the host's native presentation tools and the shared theme. Do not replace mandatory evidence with a generic layout merely because that layout is easier to generate.
