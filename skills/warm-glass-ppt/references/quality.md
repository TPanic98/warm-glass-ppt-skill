# Completion checks

Check the whole deck for narrative progression, consistent terminology, accurate values and status, slide count, title hierarchy, source attribution and repeated conclusions. For each slide, check clipping, unintended overlap, title wrapping, minimum readable type, image crop and the alignment of captions with their visual nodes.

The included builder checks input, estimated text fit and canvas bounds and creates a validation report. These checks cannot prove actual font rendering. Open the HTML design preview, then render the actual PPTX with PowerPoint, Keynote, LibreOffice or an available presentation renderer and inspect every final slide. If no PPTX renderer is available, disclose that exact gap.

Text, shapes and gradients generated by the renderer are native PowerPoint objects. PNG/JPEG/SVG artwork is an image object. A slide intentionally built from a full-page screenshot remains an image slide. Required original chart data, table content and editable relationships need a native implementation rather than a claim of universal editability.

The UI component pipeline uses native groups, attached connectors, data charts and tables, with no picture objects in the supplied component and purpose examples. Inspect unique object ids, connector references and embedded chart workbooks when changing export code. HTML uses SVG for a portable design preview; those SVGs are not embedded as pictures in the PPTX. Manually edit representative text, data and cells in a copy when a target application is available, then save and reopen it. A programmatic round trip is a different check and must be described as such.

For a user-supplied source deck, preserve the original and create a versioned output. Regenerate from the JSON brief for later changes; the generic renderer does not edit arbitrary existing PPTX files. Inspect the package with `scripts/inspect-pptx.mjs` before making editability claims.
